# M1 项目、素材与基础预览实现报告

## 状态

- 日期：2026-07-22
- 结论：M1 核心纵向流程已实现并通过自动化验证
- 下一阶段：M2 视频抽帧与人工筛查

## 1. 已实现

### 1.1 项目

- 创建和打开 `.ftproj` 目录项目。
- 项目目录包含 `project.json`、`project.db`、`cache/thumbnails` 和 `backups`。
- SQLite 迁移、WAL 模式、外键和忙等待设置。
- 打开项目时使用 SQLite `VACUUM INTO` 创建一致性备份。
- 记录最近项目，应用启动时自动尝试重开。
- 会话期间持有独占文件锁，阻止第二个进程同时写入同一项目。

### 1.2 源素材导入

- 文件选择、多文件选择、递归目录导入和 Tauri 原生拖放。
- 支持 JPEG、PNG、BMP、TIFF、WebP、MP4、MOV、MKV、AVI、WebM、M4V、MTS 和 M2TS 扩展名。
- 原地引用，不复制、修改或删除源素材。
- 保存绝对路径、大小、修改时间、64 KiB 首尾快速指纹和 SHA-256。
- 导入前台只计算快速指纹、媒体信息和缩略图，完整 SHA-256 在导入返回后统一后台补算，避免数百张图片导入期间窗口长时间没有反馈。
- 扫描目录和逐文件导入通过 Tauri 事件显示真实进度、导入/更新/忽略和失败数量。
- 同一路径重复导入更新原记录并复用缩略图，不产生重复记录或遗留缩略图。
- 单文件解码或探测失败不会阻断同批其他文件。

### 1.3 元数据与来源

- 图片读取显示尺寸、EXIF 方向和 EXIF 拍摄时间。
- 视频通过 ffprobe 读取尺寸、时长、编码、帧率和内嵌创建时间。
- 依据导入根目录下的相对文件夹生成来源组和来源标识。
- 中文、空格和 Windows Unicode 路径通过集成测试。

### 1.4 缩略图与预览

- 图片按 EXIF 方向生成 320x180 范围内 JPEG 缩略图。
- 视频通过 FFmpeg 生成首帧缩略图。
- Tauri asset protocol 只动态授权当前项目缓存和已导入源文件。
- 中央工作区支持真实图片和视频预览，底部显示最近素材缩略图。
- 左侧提供来源树、搜索、分批加载和离线状态提示。
- 右侧显示媒体信息、拍摄时间证据、快速指纹、完整哈希和原地引用路径。

### 1.5 离线恢复

- 刷新时重新计算快速指纹。
- 文件缺失或指纹变化时标记离线，不删除项目记录和已有配置。
- 重新定位要求文件类型和快速内容指纹一致，防止误绑定其他素材。

## 4. 保留项

- UI 当前一次从数据库加载最多 10,000 条源素材，左侧每次显示 500 条。PRD 的更大规模将沿用 M0 虚拟网格方案，在 M4 审核工作台实现完整虚拟滚动。
- 图片文件名拍摄时间解析规则和来源映射表属于后续来源配置界面，本阶段只使用媒体内嵌时间和默认相对目录映射。
- Tauri 原生窗口自动化运行时缺失内部依赖，本轮未生成窗口截图；该限制不影响编译、测试或媒体处理验证。
- 当前开发机 FFmpeg 是 GPL/full 构建，只用于开发验证，发行包仍须使用 M0 确认的 LGPL shared 构建。

## 5. M1 运行反馈修复

- 原测试视频由 MPEG-4 Part 2 改为 H.264 High / YUV420P，兼容 WebView2 HTML5 播放器。
- 左侧素材栏右键菜单改为应用菜单，“刷新素材状态”与右上角刷新按钮调用同一后端命令。
- 当前素材在选择前、窗口重新获得焦点时以及每 5 秒自动核对路径和快速指纹；验证失败时立即卸载缓存预览并显示离线状态。
- 手动重新定位会同步绝对路径、当前文件名、大小和修改时间。
- 改名或移动后重新导入时，若存在唯一的失联内容指纹匹配，则复用原素材 ID 并更新当前名称和来源字段。
- 多个正常来源即使内容完全相同也不会被自动合并；无法唯一判断的失联匹配保持独立，避免错误继承 ROI 或历史配置。
