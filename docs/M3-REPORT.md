# M3 ROI、切图与基础导出实现报告

## 交付范围

M3 已完成从候选图片到可追溯成品的第一条完整预处理流程：

- 多命名矩形 ROI，支持来源组预设与来源级同名覆盖。
- 画布拖拽新建 ROI，以及 X、Y、宽、高精确输入。
- 固定宽高切片、横纵重叠、丢弃、填充和贴边覆盖策略。
- 常量、边缘复制和反射填充。
- ROI 拖选与移动实时反馈，松开自动保存，并保留显式保存和保存预览操作。
- JPEG、PNG 和 WebP 编码。
- 静态原图与视频抽帧候选可直接导出；视频支持全部候选或当前候选范围，图片支持按来源组批量处理和导出。
- 视频候选与图片/视频切片均支持复选、清空选中和清空全部；切片清理作为可恢复的导出排除项处理。
- 画面变化曲线扩大默认尺寸，并提供模态放大视图。
- 来源列表分段渲染，支持批量勾选、一键选择离线/异常来源及移除项目引用。
- 移除来源只删除项目数据库记录与项目缓存，不删除磁盘原始素材；同一路径之后可以重新导入。
- 基础命名模板 AST、Windows 非法字符清理、保留设备名处理。
- 追加序号、追加短哈希、跳过和失败四种重名策略。
- 导出预演、临时文件、原子重命名和 JSONL 来源清单。
- 视频候选帧默认使用 JPEG 导出；候选缓存已经是 JPEG 且目标仍为 JPEG 时直接原子复制并计算清单哈希，不再逐张解码后转码为 PNG。
- 导出页将视频成品称为“候选原图”而不是动作“抽帧”，并显式区分“审核后保留”和“全部候选（忽略审核）”。未运行审核时，审核后保留自然包含全部候选。

## 架构实现

- storage 迁移版本提升到 3，新增独立 roi_profiles 表。
- image-pipeline 统一负责切片坐标、边缘采样、渲染和格式编码。
- application 负责有效 ROI 合并、命名模板、冲突扫描、导出计划和清单提交。
- Tauri 只暴露应用服务命令；Svelte 不直接读写数据库或处理图片。
- 预览和正式导出调用相同的 plan_tiles 与 render_tile 实现。
- 来源组导出复用单来源的 ROI、切片和命名规划，并在整个批次上统一执行冲突检测。
- 切片排除项由来源、候选、ROI、行和列共同标识，避免不同素材间误排除。
- 来源删除先清理候选和受控缓存，再删除来源级 ROI 与来源记录；缓存路径必须位于项目 cache 根目录内。

## 验证结果

- Rust workspace 全量测试通过。
- M3 纵向测试验证来源组预设、来源覆盖、四切片预览、正式导出和四行 JSONL 清单。
- 视频候选回归测试验证无 ROI 时仍可导出全部抽帧结果，并可限定当前候选帧。
- JPEG 视频候选快速导出测试验证导出字节与候选缓存一致；PNG、WebP 和切图继续经过正式渲染编码管线。
- 候选删除测试覆盖清空选中和清空全部，并验证源视频保持不变。
- 来源删除测试覆盖来源级 ROI 与缩略图缓存清理、原始素材保留及删除后重新导入。
- 来源组批量图片导出和切片排除均有应用层回归测试。
- JPEG、PNG、WebP 编解码测试通过。
- 常量、边缘复制和反射填充测试通过。
- Windows 非法字符、保留文件名和大小写不敏感重名测试通过。
- 源素材导出前后 SHA-256 保持不变。
- Svelte 检查为 0 错误、0 警告，生产构建通过。
- 1280×720 与最小 1100×700 桌面视口无页面滚动或面板重叠。
