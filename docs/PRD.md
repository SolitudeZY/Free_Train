# Free-Train 产品需求文档（PRD）

## 文档信息

- 产品名称：Free-Train
- 版本：1.0
- 状态：需求基线已确认，待实现
- 更新日期：2026-07-22
- 发行范围：个人或团队内部工具
- 运行环境：Windows 10/11，本地离线运行
- 产品类型：计算机视觉未标注素材预处理桌面软件

## 1. 产品背景

计算机视觉训练数据在进入标注平台之前，通常需要经过视频抽帧、人工筛查、ROI 裁切、固定尺寸切图、低质量图片筛除、近重复图片去重、数据增强、统一命名和来源追溯等步骤。现有流程往往依赖多个脚本或软件，参数难以复现，批量处理状态不透明，也容易误删源素材或丢失图片与原视频之间的关系。

Free-Train 将这些操作整合为一个小型、现代、可预览、可恢复的 Windows 桌面工具。所有媒体处理在本地完成，不需要账号、服务器或云端上传。

## 2. 产品定位

Free-Train 负责把本地视频和图片转换为经过人工确认、可送入后续标注流程的未标注图片，并保留完整来源追溯信息。

### 2.1 核心价值

1. 用统一界面代替零散脚本，降低重复操作成本。
2. 对关键参数提供实时预览、数量估算和磁盘估算。
3. 所有自动筛选都可审核、可撤销，不修改源素材。
4. 通过任务参数快照、随机种子和来源清单保证可复现。
5. 对不同视频、摄像头和分辨率提供来源级 ROI 与固定尺寸切图。
6. 通过独立应用服务为后续 AI Agent 和 MCP 接入保留稳定边界。

### 2.2 首版不包含

- 图片标注、标注格式转换或标注同步变换。
- train、validation、test 数据划分。
- 模型训练、评估、推理或自动识别有效事件。
- 多用户协作、账号、云存储或浏览器远程访问。
- 自动删除源视频或源图片。
- 面向公众的自动更新、遥测、崩溃上传和代码签名体系。
- 多边形 ROI、任意掩膜 ROI。
- CLIP、DINO 等语义相似度去重。

## 3. 目标用户与场景

### 3.1 主要用户

- 计算机视觉工程师。
- 数据集整理人员。
- 需要从监控、相机或实验视频中整理待标注图片的研发人员。

### 3.2 核心场景

**批量视频抽帧**：用户导入多个视频，按固定时间、固定帧间隔、目标数量或变化触发方式批量生成候选图片。

**短时有效片段筛查**：一个长视频只有几秒包含运动目标，用户播放视频、逐帧定位、手动保存精确帧，或标记多个有效片段后批量抽取。

**多摄像头 ROI 处理**：不同摄像头的有效区域不同，用户按来源或来源组配置多个矩形 ROI，并将每个 ROI 切成固定尺寸图片。

**近重复审核**：连续视频产生大量近似帧，系统自动分组并建议保留质量最佳的代表图，用户在缩略图网格中复核。

**统一命名导出**：用户将来源文件夹、拍摄时间、视频偏移、图片尺寸、ROI、切片坐标和序号自由组合成文件名模板。

## 4. 产品原则

1. **源素材不可变**：任何处理、排除和清理操作都不能修改或删除源素材。
2. **自动化可审核**：质量筛选和相似筛选只产生建议，不进行不可逆删除。
3. **快速但不盲目**：快速处理可以自动运行到审核阶段，最终导出必须确认。
4. **参数可复现**：处理任务保存输入指纹、参数快照、软件版本、算法版本和随机种子。
5. **大文件流式处理**：视频和图片不能整批载入内存，界面列表必须虚拟化。
6. **基础包保持轻量**：基础功能使用 Rust 原生实现，高级 Albumentations 能力作为未来可选扩展。
7. **职责边界清晰**：Free-Train 只生产待标注图片，不承担标注或数据划分职责。

## 5. 总体工作流

1. 创建或打开项目。
2. 原地引用导入视频、图片或文件夹。
3. 检查素材格式、元数据、离线状态和内容指纹。
4. 配置来源标识、拍摄时间解析、ROI 和处理预设。
5. 选择自动抽帧、变化触发抽帧、人工抽帧、有效片段抽帧或图片直接导入。
6. 预估候选数量、输出数量、任务耗时和磁盘占用。
7. 执行抽帧、ROI 裁切和固定尺寸切图。
8. 执行客观质量分析、精确重复检测和视觉近重复分组。
9. 在审核工作台确认保留、排除、恢复和锁定状态。
10. 选择干净导出，或选择增强配方执行可选增强导出。
11. 预览文件名、冲突处理和输出目录。
12. 用户确认后导出图片、JSONL/CSV 清单和任务报告。

## 6. 功能需求

### 6.1 项目与素材管理

**FR-PROJ-001** 用户可以创建、打开、重命名和归档本地项目。

**FR-PROJ-002** 项目保存于独立工作目录，包含 SQLite 数据库、项目配置、缩略图、中间缓存、日志和任务清单。

**FR-PROJ-003** 用户可以通过文件选择器、文件夹选择器和拖放导入单个文件、多个文件或目录。

**FR-PROJ-004** 默认原地引用源素材，不复制视频和图片到项目目录。

**FR-PROJ-005** 系统记录绝对路径、文件大小、修改时间和内容指纹，用于检测文件替换和重新定位。

**FR-PROJ-006** 源素材不可访问或指纹不一致时，标记为离线素材，不丢失 ROI、处理配置、人工标记和历史任务。

**FR-PROJ-007** 用户可以单个或批量重新定位离线素材，系统根据内容指纹提出匹配建议。

**FR-PROJ-008** 支持中文、空格、长文件名和 Windows 合法的 Unicode 路径。

**FR-PROJ-009** 支持按相对文件夹自动生成来源组和来源标识，并允许通过映射表批量覆盖，例如 `cam1_01`、`cam2_01`。

**FR-PROJ-010** 对不可读、零字节、不支持、部分损坏的文件单独报错，不中断整个批次。

### 6.2 视频预览与人工筛查

**FR-VIDEO-001** 视频播放器支持播放、暂停、拖动、逐帧前进/后退、变速、时间跳转、缩放和 ROI 叠加。

**FR-VIDEO-002** 时间轴显示当前时间、总时长、人工抽帧标记、有效片段、排除区间、变化曲线和自动抽帧位置。

**FR-VIDEO-003** 用户可以在当前实际解码时间戳执行人工抽帧，并通过按钮或快捷键连续操作。

**FR-VIDEO-004** 人工抽帧保存实际时间戳、可靠时的源帧编号、来源视频、操作人和选择方式。

**FR-VIDEO-005** 人工抽帧产生的候选图片默认锁定保留。

**FR-VIDEO-006** 锁定候选图仍显示质量警告和相似关系，但不会被自动建议排除；用户可显式解锁或排除。

**FR-VIDEO-007** 用户可以通过入点和出点标记多个有效片段，并编辑、移动或删除片段。

**FR-VIDEO-008** 有效片段支持按每秒帧数、时间间隔、帧间隔或变化峰值批量抽帧。

**FR-VIDEO-009** 有效片段生成的批量帧默认进入正常质量和相似筛选；用户可显式保护该片段产生的全部候选图。

### 6.3 自动视频抽帧

**FR-EXT-001** 支持单视频和多视频批量抽帧。

**FR-EXT-002** 支持以下抽帧模式：

- 固定时间间隔。
- 固定帧间隔。
- 按目标数量均匀抽取。
- 限定一个或多个时间范围。
- 人工时间点。
- 有效片段批量抽取。
- 画面变化触发抽帧。

**FR-EXT-003** 支持一个视频配置多个包含区间和排除区间。

**FR-EXT-004** 变帧率视频必须以实际解码时间戳为准，不能仅用固定 FPS 推算时间。

**FR-EXT-005** 抽帧前显示预计帧数、预计切片数、预计输出体积和明显的命名冲突风险。

**FR-EXT-006** 每个候选帧保存源视频、视频内偏移、源帧编号（可靠时）、抽帧方法和参数。

**FR-EXT-007** 画面变化触发抽帧可分析全画面、单个命名 ROI 或多个 ROI 的并集。

**FR-EXT-008** 变化触发模式提供变化阈值、最小输出间隔、最大兜底间隔和分析缩放尺寸。

**FR-EXT-009** 变化触发模式显示变化分数曲线和预计抽帧时间点，不把变化分数描述为 AI 事件识别结果。

**FR-EXT-010** 长时间没有明显变化时，按最大兜底间隔保留稀疏背景样本。

### 6.4 图片导入

**FR-IMG-001** 支持 JPEG、PNG、BMP、TIFF 和 WebP；具体编解码支持以发布包能力清单为准。

**FR-IMG-002** 支持递归导入子目录，并保留相对目录作为命名和来源分组字段。

**FR-IMG-003** 正确处理 EXIF 方向，并把原始方向和实际解码方向写入追溯数据。

**FR-IMG-004** 使用 SHA-256 在项目范围内检测内容完全相同的文件。

**FR-IMG-005** 检测到常见标注旁文件或数据集清单时给出提示，不静默拆散或变换已有标注。

### 6.5 ROI、缩放与固定尺寸切图

**FR-TILE-001** 同一个裁切与切图引擎同时应用于导入图片和视频抽帧候选图。

**FR-TILE-002** 每个源素材、来源组或处理预设支持一个或多个命名矩形 ROI。

**FR-TILE-003** 支持来源级 ROI 覆盖，以适应不同摄像头的有效区域差异。

**FR-TILE-004** ROI 可通过画面拖拽和 X、Y、宽、高数值输入编辑，并实时显示边界和尺寸。

**FR-TILE-005** 用户可以设置切片输出宽度和高度。

**FR-TILE-006** 横向和纵向切片重叠率可分别使用百分比或像素配置。

**FR-TILE-007** 边缘不足一个完整切片时支持：丢弃、不足处填充、最后一格贴边移动。

**FR-TILE-008** 填充模式支持常量颜色、边缘复制和反射填充；默认值由处理预设定义。

**FR-TILE-009** 支持不缩放、拉伸、等比适配并填充、等比填满并裁切、按长边或短边缩放。

**FR-TILE-010** 执行前预览切片边界、行列编号、来源坐标、数量、重叠、填充和文件名示例。

**FR-TILE-011** 每个切片记录其相对源素材和 ROI 的坐标、行列编号和切图配置版本。

**FR-TILE-012** 首版不支持多边形 ROI 和任意掩膜。

### 6.6 客观质量分析

**FR-QA-001** 检测图片和帧的解码失败或损坏状态。

**FR-QA-002** 测量分辨率、宽高比、清晰度、过曝比例、欠曝比例和低信息量程度。

**FR-QA-003** 支持配置最小分辨率、允许宽高比范围、模糊阈值、曝光阈值和低信息量阈值。

**FR-QA-004** 调整阈值时显示两侧代表样本和预计影响数量。

**FR-QA-005** 支持按来源查看质量指标分布，并按指标筛选和排序候选图。

**FR-QA-006** 质量分析只产生错误、警告或建议排除状态，不物理删除源素材。

**FR-QA-007** 保存算法版本、测量值、阈值版本、建议原因和人工覆盖记录。

**FR-QA-008** 首版不使用模型判断画面内容是否“有价值”。

### 6.7 精确重复与视觉近重复筛选

**FR-SIM-001** 使用 SHA-256 在整个项目内识别内容完全相同的文件。

**FR-SIM-002** 使用 pHash 召回视觉近重复候选，使用 SSIM 对阈值临界候选进行二次确认。

**FR-SIM-003** 普通模式提供严格、平衡、宽松预设和直观相似度滑块。

**FR-SIM-004** 高级模式显示并允许配置 pHash 汉明距离、SSIM 阈值和视频时间窗口。

**FR-SIM-005** 默认感知相似比较范围为同一源素材、同一命名 ROI、同一切片位置，并满足视频时间窗口。

**FR-SIM-006** 未切图的静态图片不受切片位置限制。

**FR-SIM-007** 来源组、全项目和跨切片位置比较只能在高级模式显式启用，并显示误删风险。

**FR-SIM-008** 对大型任务使用时间窗口、索引或近邻结构，禁止无约束全量两两比较。

**FR-SIM-009** 相似结果必须形成相似组，不直接生成不可解释的两两删除链。

**FR-SIM-010** 系统根据清晰度、曝光、分辨率和压缩退化等客观指标建议代表图；视频候选质量接近时优先时间上更居中的帧。

**FR-SIM-011** 完全同分时按时间戳和稳定来源顺序决定，保证重复运行结果一致。

**FR-SIM-012** 锁定候选图优先成为代表图；一个组内有多个锁定候选图时要求人工确认。

**FR-SIM-013** 首版不使用 CLIP、DINO 或其他语义嵌入进行去重。

### 6.8 人工审核

**FR-REV-001** 审核页同时显示保留、建议排除、质量警告、锁定和失败状态。

**FR-REV-002** 建议排除图片使用浅白色半透明蒙层和清晰选中标记。

**FR-REV-003** 支持保留、排除、恢复、锁定、解锁、整组保留、排除选中和更换代表图。

**FR-REV-004** 支持相似图片并排对比、同步缩放、元数据查看、相似分数和视频时间戳查看。

**FR-REV-005** 支持按状态、来源、ROI、切片位置、质量原因、相似组和人工/自动来源筛选。

**FR-REV-006** 审核操作支持撤销和重做，并保存操作人、时间和原因。

**FR-REV-007** 导出前显示保留数量、排除数量、失败数量、增强后预计数量和预计磁盘占用，并提供最终复核入口。

### 6.9 数据增强

**FR-AUG-001** 默认导出模式为不增强的干净导出。

**FR-AUG-002** 增强以配方形式保存和预览，不在配置阶段永久生成图片。

**FR-AUG-003** 用户显式选择增强导出后，才在最终导出阶段生成增强变体。

**FR-AUG-004** 首版 Rust 增强执行器支持：

- 缩放、旋转、水平/垂直翻转、平移、随机裁切、填充。
- 仿射和透视变换。
- 亮度、对比度、Gamma、饱和度、色相、色温、高光和阴影。
- 高斯模糊、运动模糊、锐化。
- 高斯噪声、椒盐噪声和基础传感器噪声模拟。
- JPEG 压缩损伤、雾化和暗角等基础效果。

**FR-AUG-005** 每项增强支持启用状态、执行概率、参数范围和操作顺序。

**FR-AUG-006** 支持配置每张候选图的变体数量和固定随机种子。

**FR-AUG-007** 配方界面预览多个随机结果，预览与最终导出在相同种子和参数下保持一致。

**FR-AUG-008** 对垂直翻转等可能破坏领域语义的操作显示风险提示。

**FR-AUG-009** 原候选图和全部增强变体共享 `lineage_group_id`。

**FR-AUG-010** 每张增强成品记录执行器名称、执行器版本、随机种子和实际应用参数。

**FR-AUG-011** 提示用户：标注前增强会增加后续标注数量。

**FR-AUG-012** 预留可选增强执行器接口；未来 Albumentations 扩展不属于基础安装包。

### 6.10 自由命名与导出

**FR-EXP-001** 用户可以自由组合、排序和格式化命名字段，并保存命名预设。

**FR-EXP-002** 首版字段至少包括：

- 源文件名。
- 相对来源文件夹。
- 来源标识。
- 拍摄时间及其证据来源。
- 视频内偏移或毫秒值。
- 处理时间。
- 原始宽高和输出宽高。
- ROI 名称。
- 切片行列和源坐标。
- 处理任务标识。
- 增强变体标识。
- 血缘组标识。
- 导出模式。
- 可配置位数的递增序号。

**FR-EXP-003** 支持 `YY-MM-DD-HH` 等时间格式，并在缺少秒或序号时提示潜在重名。

**FR-EXP-004** 拍摄时间按媒体内嵌时间、文件名解析规则、文件系统创建时间、用户手动值的顺序解析。

**FR-EXP-005** 系统必须保存拍摄时间证据来源；不得静默使用处理时间冒充拍摄时间。

**FR-EXP-006** 字段不可用时显示占位或校验错误，不伪造精确值。

**FR-EXP-007** 示例模板：`{source_id}_{capture_time:YYMMDDHHmmss}_{video_offset_ms}_{width}x{height}_{seq:06}`。

**FR-EXP-008** 实时预览多个实际文件名，并在导出前扫描重名和 Windows 非法字符。

**FR-EXP-009** 重名策略支持追加序号、追加短哈希、跳过或导出前失败；禁止静默覆盖。

**FR-EXP-010** 支持 JPEG、PNG 和 WebP 导出及对应质量/压缩设置。

**FR-EXP-011** 可选保留相对来源目录结构。

**FR-EXP-012** 同步导出 JSONL 或 CSV 清单，包含来源、处理参数、审核状态、质量测量、相似关系、增强参数和内容哈希。

### 6.11 快速处理、任务与缓存恢复

**FR-JOB-001** 快速处理使用已保存预设，一键执行校验、估算、抽帧/导入、ROI/切图、质检和相似分组，然后停在审核阶段。

**FR-JOB-002** 高级处理允许逐阶段配置、预览和运行。

**FR-JOB-003** 最终导出必须由用户确认，快速处理不得自动导出或删除任何内容。

**FR-JOB-004** 显示总体和单来源进度、当前阶段、已用时间、预计剩余时间、输出数量、错误和警告。

**FR-JOB-005** 支持任务排队和可配置并发度。

**FR-JOB-006** 支持取消；可确定恢复的阶段支持暂停和继续。

**FR-JOB-007** 输出文件使用临时文件和原子重命名，避免出现被误认为成功的半写入文件。

**FR-JOB-008** 应用异常退出后，项目能够识别中断任务并恢复未完成阶段。

**FR-JOB-009** 输入指纹和阶段参数未变化时，不重复生成已完成结果。

**FR-JOB-010** 修改上游参数只使受影响的下游缓存失效，不清理无关阶段。

**FR-JOB-011** 单个来源失败不影响同任务中其他来源的成功结果，并生成失败报告。

**FR-JOB-012** 缓存清理必须明确列出目标、可释放空间和影响；不能包含源素材。

### 6.12 设置、日志与诊断

**FR-SYS-001** 提供项目设置和应用设置，区分项目级预设与全局默认值。

**FR-SYS-002** 提供 FFmpeg 能力、WebView2 状态、磁盘空间、数据库版本和应用版本诊断信息。

**FR-SYS-003** 日志默认不记录图片内容；敏感绝对路径仅在用户启用诊断导出时包含。

**FR-SYS-004** 内部首版不包含遥测、崩溃自动上传和自动更新。

**FR-SYS-005** 提供标准安装包和便携版；标准安装包检测 WebView2，缺失时允许安装阶段联网补齐。

### 6.13 MCP 接入预留

**FR-MCP-001** 桌面 UI 通过 Rust 应用服务访问项目和处理能力，不直接操作底层数据库或任意文件路径。

**FR-MCP-002** 桌面 MVP 不开放公共 MCP Server。

**FR-MCP-003** 后续候选 MCP 能力包括项目读取、素材列表、参数校验、任务估算、创建任务、查询进度、读取审核建议和读取导出清单。

**FR-MCP-004** MCP 文件访问必须限制在用户授权根目录。

**FR-MCP-005** 读取和修改操作使用不同权限；导出、缓存清理和越界写入需要桌面端确认。

**FR-MCP-006** MCP 操作保存调用者、参数摘要、项目、结果和时间审计记录。

## 7. 界面与交互要求

### 7.1 总体布局

- 使用现代 Windows 工作台式三栏布局，不采用传统灰色表单或向导式堆叠页面。
- 左侧为项目与素材导航，中间为视频/图片预览或审核网格，右侧为当前上下文参数。
- 顶部工具栏放置导入、预估、快速处理、取消和导出等明确命令。
- 底部状态区显示任务、数量、错误和磁盘状态。
- 面板可拖动调整，中央工作区优先获得空间。

### 7.2 视觉风格

- Svelte/HTML/CSS 构建现代界面，支持浅色、深色和跟随系统。
- 使用中性背景，蓝色表示主要操作，绿色表示保留，橙色表示警告，红色表示错误。
- 卡片圆角不超过 8px，避免大面积渐变、装饰性圆球和营销页式布局。
- 使用统一图标库和紧凑工具栏；高频工具优先使用图标并提供提示。
- 缩略图、播放器和固定格式控件使用稳定尺寸，加载或状态变化不能引起布局跳动。

### 7.3 高效审核

- 缩略图网格采用虚拟滚动和渐进加载。
- 选择、筛选和缩放状态在缩略图加载时保持稳定。
- 支持键盘执行保留、排除、恢复、锁定、下一张、上一张和对比。
- 视频人工筛查支持播放/暂停、逐帧、设置入点/出点、人工抽帧和跳转标记。

## 8. 非功能需求

### 8.1 兼容性与发行

- 支持 Windows 10 和 Windows 11。
- 最低目标：4 核 CPU、8 GB 内存，无独立显卡。
- 推荐目标：8 核 CPU、16 GB 内存、SSD。
- 标准安装包目标约 40-70 MB，依赖系统 WebView2，并携带精简 FFmpeg/ffprobe。
- 不在运行包中携带 Python、Qt、OpenCV、Node.js 或 Chromium。
- 缺少 WebView2 时安装程序可联网安装；软件安装后所有处理功能离线运行。

### 8.2 性能与规模

- 支持常见 1080p 和 4K H.264/H.265 视频。
- 单任务设计规模约 100 个视频或 100,000 张图片。
- 单项目设计规模约 1,000,000 条候选图片元数据。
- 普通任务内存占用目标低于 4 GB，不包含异常大的第三方编解码缓冲。
- 缓存命中时，推荐硬件上的缩略图或图片切换目标低于 300 ms。
- 取消请求应在当前不可中断的解码或文件操作结束后尽快生效。
- 具体吞吐目标在实现阶段通过代表性测试素材建立基线。

### 8.3 可靠性

- 相同输入、参数、算法版本、软件版本和随机种子必须得到相同结果。
- 数据库使用版本化迁移。
- 任务、阶段和文件写入具备中断恢复能力。
- 单文件错误不能导致整个批次结果丢失。
- 导出过程禁止静默覆盖。

### 8.4 安全与隐私

- 源素材不可修改、不可由普通处理操作删除。
- 默认不联网、不上传、不遥测。
- 外部进程调用使用结构化参数，不拼接未校验的 Shell 命令。
- 所有导出和缓存路径在执行前进行规范化与边界校验。
- 后续 MCP 必须使用允许目录、权限分层和审计记录。

## 9. 技术方案基线

- 桌面壳：Tauri 2。
- 前端：Svelte + TypeScript + Vite。
- UI 渲染：Windows WebView2。
- 核心服务：Rust。
- 视频：精简 FFmpeg/ffprobe 子进程适配器。
- 图片处理：Rust 原生图片、几何、哈希、SSIM、颜色和编码库。
- 并发：Rust 有界任务队列与 CPU 工作线程池。
- 元数据：SQLite。
- 配置与清单：Serde JSON、JSONL、CSV。
- 基础增强：Rust 原生增强执行器。
- 高级增强：未来可选 Albumentations 执行器。
- MCP：桌面 MVP 后续通过 Rust 适配器接入。

## 11. 验收标准

**AC-001** 用户能在无 Python 环境的 Windows 10/11 机器安装并运行标准安装包。

**AC-002** 用户能在一个项目中导入混合视频和图片目录，离线素材不会导致项目无法打开。

**AC-003** 用户能从多个视频按固定时间间隔和目标数量抽帧，并获得准确视频内时间戳。

**AC-004** 用户能逐帧定位视频并手动保存精确帧，也能标记多个有效片段进行批量抽取。

**AC-005** 用户能预览变化曲线并执行变化触发抽帧。

**AC-006** 用户能为不同来源设置多个矩形 ROI，并按固定宽高、重叠率和边缘策略切图。

**AC-007** 用户能调整质量阈值并预览阈值两侧样本，系统不会物理删除源素材。

**AC-008** 用户能查看相似组、浅白蒙层建议排除图、代表图和相似分数，并恢复任意候选图。

**AC-009** 人工抽帧默认锁定，不会因自动规则失去导出资格。

**AC-010** 用户能自由组合命名字段并在导出前发现所有重名问题。

**AC-011** 每张导出图片都能通过清单追溯到源素材、时间戳、ROI、切片坐标、审核状态和处理参数。

**AC-012** 可选增强导出在相同种子和配方下产生一致结果，并记录实际增强参数。

**AC-013** 一个来源处理失败不影响同任务其他来源成功，失败原因可查看。

**AC-014** 应用异常退出后可识别中断任务，并在输入和参数未变化时继续未完成阶段。

**AC-015** 快速处理停在审核阶段，只有用户确认后才写出最终成品。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| WebView2 缺失 | 小型安装包无法直接启动 | 安装阶段检测并联网补齐，后续提供大型离线包 |
| FFmpeg 体积或许可证 | 增大安装包并影响分发 | 精简构建、维护能力和许可证清单、只启用必要组件 |
| Rust 图片增强生态不足 | 高级增强开发成本增加 | 首版限定基础集合，预留版本化可选执行器 |
| pHash/SSIM 误判 | 有效图片被建议排除 | 限定默认比较范围、相似组审核、锁定与恢复 |
| 大项目缩略图卡顿 | 审核效率下降 | 虚拟列表、分级缓存、后台解码、稳定缩略图尺寸 |
| 源素材移动或替换 | 项目失去引用 | 内容指纹、离线状态、批量重新定位 |
| 标注前增强增加工作量 | 后续标注量变大 | 默认干净导出，增强导出显式启用并提示数量 |
| 任务中断产生半成品 | 用户误认为处理完成 | 原子写入、阶段检查点、任务恢复和不完整标记 |

## 13. 已确认决策

- 项目独立位于 `E:\Python_Prj\Free-Train`。
- 首版是 Windows 本地离线、单用户、内部使用工具。
- 首版只处理未标注素材，不进行标注和数据划分。
- 技术栈为 Tauri 2、Svelte/TypeScript、Rust、SQLite 和精简 FFmpeg/ffprobe。
- 标准安装包依赖系统 WebView2，缺失时可在安装阶段联网补齐。
- 源素材默认原地引用并保持不可变。
- 支持多个矩形 ROI，不支持多边形 ROI。
- 感知相似默认限定同来源、同 ROI、同切片位置和视频时间窗口。
- 去重使用 SHA-256、pHash 和 SSIM，不使用语义模型。
- 自动筛选只提供可撤销建议，不物理删除源素材。
- 人工抽帧默认锁定保留。
- 快速处理自动运行到审核阶段，最终导出必须确认。
- Free-Train 不生成 train、validation、test 划分。
- 默认干净导出；增强配方只在可选增强导出时生成变体。
- 基础增强使用 Rust；高级 Albumentations 能力作为未来可选扩展。
- 桌面 MVP 不开放 MCP Server，但从首版保留应用服务边界。
